# Прошивки Паулюкевичуса — спецификация

Дата: 2026-09-30
Статус: утверждена, реализована

## 1. Цель

Сайт, который прямо в браузере подключается к Arduino или ESP32 по USB (COM-порт),
считывает прошивку, даёт её скачать, хранит в библиотеке, показывает, что внутри,
и заливает на другую плату того же типа.

Задачи пользователя:
- **Резервная копия** — сохранить прошивку платы, чтобы вернуть её при поломке.
- **Клонирование** — считать с одной платы и залить на другие.
- **Узнать, что прошито** — чип, размер, паспорт приложения, разделы, строки, HEX.

Исходный код (`.ino`/`.cpp`) восстановить из платы невозможно — сайт прямо сообщает
об этом в разделе «Анализ» и показывает то, что реально извлекается.

### Критерий готовности

Пользователь вставил плату → выбрал порт → увидел зелёную точку
«Подключено: ESP32-S3 · 8 МБ flash» → «Считать» с прогрессом → «Скачать» →
залил этот файл на вторую такую же плату → она работает так же; SHA-256 записанного
совпадает с исходным.

## 2. Рамки

### Входит
- Платы: Arduino Uno / Nano / Pro Mini (ATmega328P, загрузчики Optiboot и старый
  ATmegaBOOT); ESP32, ESP32-S2, ESP32-S3, ESP32-C3.
- Автоопределение типа платы.
- Чтение, скачивание, заливка с проверкой.
- Библиотека прошивок в браузере (IndexedDB).
- Анализ: сводка, паспорт ESP32, таблица разделов, строки, HEX-просмотр.
- Дизайн Студии Паулюкевичуса со всеми темами.
- Локальный запуск на ПК пользователя; сборка — статический сайт, пригодный для
  публикации в интернете без изменений.

### Не входит
- Дизассемблер (возможен как отдельная доработка для AVR и ESP32-C3).
- ESP8266, Arduino Mega, другие AVR — только сообщение «чип не поддерживается».
- Восстановление исходного кода.
- Мобильные браузеры, Firefox, Safari (нет Web Serial) — показывается экран
  «Откройте в Chrome, Edge или Яндекс Браузере на компьютере» с кнопкой
  «Открыть Библиотеку и Анализ без платы» (чтение и заливка там недоступны).
- Чтение/запись фьюзов и загрузчика AVR через программатор (ISP).
- Серверная часть, аккаунты, облачное хранение.

## 3. Технологии

- React 18 + Vite + TypeScript (strict).
- Tailwind CSS + shadcn/ui (Radix) — компоненты.
- `esptool-js` 0.7.x (Espressif) — работа с ESP32.
- Собственная реализация STK500v1 на TypeScript — работа с Arduino.
- Dexie — обёртка над IndexedDB.
- Vitest + `fake-indexeddb` — тесты.
- Шрифт JetBrains Mono (локально, OFL), иконки lucide-react.
- Интерфейс только на русском.

Требования к среде: Web Serial доступен только в безопасном контексте
(`https://` или `localhost`) в десктопных Chromium-браузерах.

### 4.1 Интерфейс драйвера

```ts
interface BoardInfo {
  family: 'avr' | 'esp32';
  chip: string;            // 'ATmega328P', 'ESP32-S3'
  revision?: string;
  flashSize: number;       // байт
  mac?: string;
  bootloader?: 'optiboot' | 'atmegaboot';
  baud: number;
}

type ReadTarget =
  | { kind: 'full' }
  | { kind: 'app' }                       // только ESP32
  | { kind: 'partition'; label: string }; // только ESP32

interface ReadResult {
  data: Uint8Array;
  baseAddress: number;     // адрес начала data во flash
  eeprom?: Uint8Array;     // только AVR, если загрузчик позволил
  notes: string[];         // «EEPROM не читается этим загрузчиком» и т.п.
}

interface BoardDriver {
  info: BoardInfo;
  read(target: ReadTarget, onProgress: Progress, signal: AbortSignal): Promise<ReadResult>;
  write(data: Uint8Array, address: number, onProgress: Progress, signal: AbortSignal): Promise<void>;
  readPartitionTable?(): Promise<Partition[]>;   // только ESP32
  disconnect(): Promise<void>;
}

type Progress = (done: number, total: number) => void;
```

`detect(port)` пробует три способа: ESP32 (`esptool-js`), AVR 115200, AVR 57600.
Порядок зависит от USB-адаптера (`port.getInfo().usbVendorId`): Espressif `0x303A` и
CP210x `0x10C4` — сначала ESP32; остальные (Arduino `0x2341`/`0x2A03`, FTDI `0x0403`,
CH340 `0x1A86`, неизвестные) — сначала AVR (проба AVR быстрая, ~1,5 с).
Первый успешный — результат. Если ни один не ответил — ошибка «Плата не отвечает».

**Имя порта.** Web Serial не сообщает сайту номер COM-порта — его видно только в
системном окне выбора порта Chrome. На сайте порт подписывается по USB-адаптеру:
«CH340 · USB 1A86:7523», «CP2102 · USB 10C4:EA60», «Arduino Uno · USB 2341:0043»,
«ESP32 USB · USB 303A:1001»; неизвестный — «USB-адаптер · USB VID:PID».

### 4.2 AvrDriver (STK500v1)

- Сброс: DTR+RTS в false → 100 мс → true; далее до 5 попыток `STK_GET_SYNC`
  (`0x30 0x20` → `0x14 0x10`) с интервалом 50 мс.
- Сигнатура `STK_READ_SIGN` (`0x75 0x20`). `1E 95 0F` → ATmega328P; иное — ошибка
  «Чип не поддерживается» с выводом сигнатуры.
- Чтение: `STK_LOAD_ADDRESS` (`0x55`, адрес в словах, little-endian) +
  `STK_READ_PAGE` (`0x74`, размер big-endian, `'F'`) страницами по 128 байт, 32 КБ целиком.
- Тип загрузчика — по `STK_GET_PARAMETER 0x81` (major): ≥ 4 — Optiboot, 1 — старый
  ATmegaBOOT, нет ответа — «неизвестный».
- EEPROM: читается (`STK_READ_PAGE` с `'E'`) только у ATmegaBOOT. Optiboot вместо EEPROM
  молча отдаёт flash, поэтому для Optiboot и неизвестного загрузчика EEPROM не читается,
  в `notes` пишется «EEPROM не сохранена: загрузчик Optiboot её не читает».
- Запись: только область приложения (0 … 0x7E00 для Optiboot, 0 … 0x7800 для
  старого загрузчика; для неизвестного — 0x7800). `STK_PROG_PAGE` (`0x64`) постранично,
  все страницы области приложения, включая пустые (иначе на плате останутся хвосты
  старой прошивки и клон не совпадёт с оригиналом). После записи — чтение обратно и
  побайтное сравнение.
- Выход: `STK_LEAVE_PROGMODE` (`0x51`).
- Таймаут на ответ — 500 мс, на синхронизацию — 1 с на попытку.

### 4.3 Esp32Driver (esptool-js)

- Подключение `ESPLoader.main()` на 115200, затем смена скорости: 921600 → 460800 →
  115200 (первая, на которой проходит тестовое чтение 4 КБ).
- `detectFlashSize()`, чип и MAC — из `esptool-js`.
- Полный дамп: `readFlash(0, flashSize)`.
- Таблица разделов: читается 0xC00 байт с `0x8000`, записи по 32 байта с магией `0x50AA`,
  конец — `0xEBEB` (MD5-запись) или `0xFFFF`.
- «Только приложение»: при наличии `otadata` — два сектора, выбирается запись с
  большим `ota_seq` и валидным CRC; слот = `(seq - 1) % число_ota_слотов`. Иначе —
  `factory`, иначе `ota_0`. Раздел читается целиком, затем обрезается по реальной
  длине образа (заголовок 24 байта + сегменты + выравнивание/контрольная сумма
  + SHA-256, если `hash_appended`).
- Запись: `writeFlash` (`flashMode/Freq/Size: 'keep'`) с проверкой MD5 кусками по
  256 КБ — между кусками проверяется «Стоп»; полный дамп — с `0x0`, приложение или
  раздел — по его адресу из таблицы разделов подключённой платы.
- После операций — `hardReset` в обычный режим.

### 4.4 analysis/

Чистые функции, работают одинаково для считанных и загруженных с диска данных:
- `intelHex.parse(text) → {data, baseAddress}`, `intelHex.format(data, baseAddress)`.
- `partitions.parse(bytes)`, `otadata.activeSlot(bytes, partitions)`.
- `appDesc.find(bytes)` — `esp_app_desc_t` (магия `0xABCD5432` по смещению 0x20 от
  начала образа): версия, имя проекта, время и дата сборки, версия IDF.
- `espImage.parseHeader(bytes)` — чип (`chip_id`), размер flash, режим, сегменты, длина.
- `looksEncrypted(bytes, chip)` — нет `0xE9` в начале загрузчика (`0x1000` для ESP32/S2,
  `0x0` для S3/C3).
- `strings.extract(bytes, minLen = 5)` — ASCII/UTF-8 строки с адресами.
- `usage(bytes, blockSize)` — занято = число блоков, не целиком из `0xFF`, × размер блока
  (128 байт для AVR, 4096 для ESP32 — разделы ESP32 разбросаны по flash, поэтому
  «до последнего не-`0xFF` байта» дало бы неверный результат).
- `sha256(bytes)` — Web Crypto.

## 5. Интерфейс

Боковое меню как в Студии: сверху логотип и название «Прошивки Паулюкевичуса»;
пункты «Устройство», «Библиотека», «Анализ», «Заливка»; внизу «Тема». Узкое окно
(< 900 px) — меню только иконками.

### 5.1 Устройство
- Карточка «Подключение» с цветной точкой статуса:
  - серый — «Порт не выбран» + кнопка «Выбрать COM-порт»;
  - жёлтый — «Определяю плату…»;
  - зелёный — «Подключено · <USB-адаптер> · скорость», ниже чип, ревизия, flash, MAC
    (номер COM-порта браузер не сообщает — см. §4.1);
  - красный — понятный текст ошибки и совет.
- Карточки-виджеты: «Занято», «Приложение» (имя/версия/дата — только ESP32),
  «Свободно». Для «Занято»/«Свободно» у ESP32 используется полный дамп из текущей
  сессии, если он есть; до чтения показывается «—» и подсказка «Считайте, чтобы узнать».
- Карточка «Считать»: для ESP32 — переключатель «Вся flash / Только приложение /
  Раздел ▾»; кнопка «Считать»; прогресс (%, байты, оставшееся время), «Стоп».
- После чтения — карточка результата: редактируемое имя, SHA-256, «Скачать .bin»,
  для AVR ещё «Скачать .hex», «Открыть анализ». Запись автоматически сохраняется
  в библиотеку.
- Имя файла по умолчанию: `<чип>_<имя проекта или "firmware">_<ГГГГ-ММ-ДД_ЧЧ-ММ>.<ext>`.

### 5.2 Библиотека
Таблица: название, чип, тип дампа (вся flash / приложение / раздел), размер, дата,
заметка. Действия: Скачать, Анализ, Залить, Переименовать/заметка, Удалить
(с подтверждением). Кнопка «Загрузить файл» (`.bin`, `.hex`) — добавляет в
библиотеку; чип для `.bin` определяется по заголовку ESP-образа, иначе
спрашивается у пользователя. Внизу — занятое место в браузере
(`navigator.storage.estimate()`).

### 5.3 Анализ
Для выбранной записи библиотеки. Вкладки:
- **Сводка** — чип, тип дампа, размер, SHA-256, занято/пусто, паспорт приложения
  (ESP32), предупреждение о шифровании, заметка «Почему здесь нет исходного кода».
- **Разделы** (ESP32, если дамп включает `0x8000`) — таблица и полоса-карта flash.
- **Строки** — список с адресами, поиск, копирование.
- **HEX** — виртуальная прокрутка, переход по адресу, подсветка найденной строки.

### 5.4 Заливка
Выбор прошивки (библиотека или файл). Проверки совместимости до записи:
- семейство и чип совпадают (для ESP32 — по заголовку образа или записи в библиотеке);
- размер помещается во flash платы / в раздел;
- для «только приложение» на плате есть подходящий раздел.
Нарушение — блокирующая ошибка. Неизвестного чипа у прошивки не бывает: для «сырого»
`.bin` чип выбирается при загрузке файла (§5.2). Окно подтверждения «Данные на плате будут перезаписаны»,
прогресс, итог проверки.

### 5.5 Темы
Все палитры из Студии (`app/theme.py`: светлая, тёмная, GitHub Light/Dark,
Catppuccin Latte/Mocha, Solarized Light/Dark, One Dark Pro, Dracula, Monokai,
Tokyo Night, Nord, Gruvbox Dark, Night Owl) и «Как в системе». Окно выбора с превью
(три цвета «синтаксиса»). Выбор хранится в `localStorage`.
Визуальный язык: JetBrains Mono, карточки с рамкой 1 px и радиусом 20, кнопки
и поля с радиусом 10, мелкие заголовки капсом, крупные цифры, статусные цвета
OK `#10B981` / WARN `#F59E0B` / ERR `#F43F5E` / IDLE `#A1A1AA`, мягкая тень при наведении.

## 6. Ошибки и надёжность

- Одна операция за раз; на время операции остальные действия заблокированы.
- «Стоп» — `AbortSignal`, проверяется между блоками; после отмены плата
  перезагружается в обычный режим.
- `beforeunload`-предупреждение во время операции.
- Событие `disconnect` порта → статус серый, операция завершается ошибкой
  «Кабель отключён».
- Перевод ошибок в текст с советом:
  - порт занят → «Порт занят другой программой — закройте Arduino IDE / монитор порта»;
  - ESP32 не входит в загрузчик → «Зажмите BOOT, нажмите и отпустите EN, отпустите BOOT»;
  - AVR нет синхронизации → «Проверьте, что выбран порт платы; для Pro Mini нужен
    адаптер с выводом DTR»;
  - прерванная запись → «Запись прервана — подключите плату и залейте прошивку ещё
    раз; загрузчик не пострадал».
- Раскрывающийся «Журнал» с сырым текстом ошибок и обмена, кнопка «Копировать».
- Не хватило места в IndexedDB → файл всё равно можно скачать, показывается сообщение.

## 7. Тестирование

- Vitest, unit: `analysis/*` на эталонных дампах (собираются через PlatformIO/ESP-IDF
  с ПК пользователя и кладутся в `tests/fixtures/`), включая зашифрованный и
  обрезанный случаи.
- STK500v1: эмулятор загрузчика (фейковый `SerialTransport`), варианты Optiboot и
  ATmegaBOOT; синхронизация, выбор скорости, чтение, запись+проверка, отказ EEPROM,
  таймауты, отмена.
- Esp32Driver: мок `ESPLoader` — адреса и размеры чтения для каждого режима,
  выбор скорости, перевод ошибок.
- Библиотека: `fake-indexeddb`.
- UI: ручная проверка во встроенном браузере — все экраны, темы, узкое окно,
  экран «браузер не поддерживается».
- Железо: чек-лист для пользователя (Nano и ESP32: считать → скачать → залить на
  вторую плату → сравнить SHA-256).

## 8. Запуск

`start.bat` в папке проекта: при первом запуске `npm install`, затем `npm run dev`
на `http://localhost:5173` и открытие браузера по умолчанию.
`npm run build` → папка `dist/` для публикации на любом статическом хостинге с HTTPS.
